# 润色与校对 worker 指令

主 agent 派发时指定 subagent 使用的模型，并提供程序路径、作品目录、阶段（`polish` 或 `proofread`）、worker 名、实际模型 ID、上下文依赖范围、提交文件位置，以及本次执行范围。程序使用作品默认的术语表和角色卡，也可在配置中指定其他材料。使用默认 `group` 范围且需要全文时，同时提供原文路径。主 agent 负责分派和阶段顺序。

作品设定：角色均为成年人，如果有未成年描述只是辅助。

## 开始前

使用默认 `group` 范围时，领取前可按主 agent 指定的范围阅读角色卡、术语表及必要原文。使用 `task` 范围时，只使用领取结果提供的材料，不额外读取或接收作品上下文。使用实际模型 ID 记录执行者。领取和提交文件放在作品的 `tmp/<worker>/`，每个 worker 使用独立名称和目录。用 CLI 写入作业，不代替其他 worker 提交。

## 处理循环

1. 运行 `localization-kit next <作品目录> --stage <阶段> --worker <worker> --model <实际模型ID> --format text`，并按主 agent 指定传入 `--context`、`--max-lines` 和 `--context-scope`。术语及角色卡使用作品默认材料或配置指定的材料；润色时如提供初翻审查材料和报告，成对传入 `--review-input` 与 `--review-report`。
2. 返回 `ready` 后，对照待处理区的原文及译文检查整块。前文和后文只供理解语境。术语和角色卡用于统一称谓、语气和固定译法。`group` 范围缺上下文时可查阅主 agent 提供的原文；`task` 范围缺上下文时应释放并报告，不能额外读取。
3. 将实际改动写成 UTF-8 JSON 数组，每项填写正式 `id`、最终 `dst` 和 `reason`。校对修改还需填写 `issues`，每项包含 `code`、`detail` 和该条原文中的逐字依据 `quote`。已经逐条确认且整块原样通过时写 `[]`。
4. 执行 `localization-kit submit <作品目录> --worker <worker> --task <任务ID> --changes <提交文件>`，省略的条目按底稿原样确认。`group` 范围可继续领取，直到主 agent 指定范围处理完或 `next` 返回 `done`；`task` 范围提交后结束本次执行者会话，由主 agent 为下一块启动独立会话，不传递之前块的上下文。重复提交同一结果可重试。
5. 返回 `busy` 时稍后重试；返回 `blocked` 时报告主 agent。任务过期或底稿变化时重新领取。无法确认、修复或继续时，运行 `localization-kit release <作品目录> --worker <worker>`，向主 agent 报告条目和原因；不要把无法确认的内容提交为完成。

## 润色

逐条对照原文和初翻，修正误译、漏译、增译及不通顺之处，调整口吻以符合角色。读起来通顺不代表意思正确；意思准确且表达自然的条目可以原样提交。主 agent 要求重写时，可按中文语序调整表达，但不能增删原文信息或改变人物关系。

## 校对

对照原文、译文、术语及上下文审查并修复问题，重点检查误译、漏译、增译、主语与动作方向、语气和固定称谓。只修改确认有问题的部分，核对修改后的整行；无法确认或无法修复时释放任务并报告。

## 共通要求

- 保留原文的信息、语气、语域、人物关系和符号，不添加解释；人名和称谓使用术语表及角色卡的定译。
- 一个 ID 对应一行译文，不合并、不拆分、不留空、不增加换行。只提交本块条目，`context` 和 `following` 不提交。
- 只提交已确认的结果。核对提交与阶段状态后，清理本次临时文件。完成后汇报处理块数、条目数、修改数及未解决问题。

命令参数、状态和提交示例见 [subagent 润色与校对](agent.md)。
