# 翻译质量比较与评测

本文介绍作业比较和译文评测。模型部署及 GPU 调度由 ops 负责，质量评估与生产切换的结论应分别记录。

## 作业比较

用同一份输入和术语条件分别运行两个作业，再比较结果：

```sh
localization-kit eval compare --baseline baseline --candidate candidate --out comparison.json
```

程序校验两个作业的完整输入条目一致，报告各作业的完成、失败、待处理、待复核及各类警告和违规次数，以及逐条原文、译文、模型信息和已有 usage。仅将两边均完成、无需复核且非原样保留的条目计入相同或不同；其他条目计为未配对。输出必须是新文件，且位于两个作业目录之外。结果相同或不同只表示文本是否一致，不能直接判断翻译质量。

## 准备盲评与统计

```sh
localization-kit eval blind-prepare --input comparison.json --out evaluation --batch-size 20
```

程序为不同译文生成两轮换位批次，各轮顺序独立打乱。`evaluation/batches/` 内是待评原文、同组前文和匿名译文；`evaluation/key.json` 包含答案及作业来源，必须由组织者保管，只向评审提供批次文件。两轮应分开发给评审。相同译文、未完成、待复核或原样保留的条目不进入盲评；仅标点不同的译文也会进入。

评审为每个批次生成同名 JSON，写入独立的 `reports/` 目录。例如 `1-0001.json`：

```json
{"batch_hash":"批次文件中的 hash","items":[{"token":"批次条目的 token","winner":"a","reason":"判断依据"}]}
```

每个批次必须覆盖全部 token。`winner` 为 `a`、`b`、`tie` 或 `refused`；结果文件应先写至临时路径，完成后再发布到结果目录。提交和查看全部报告后运行：

```sh
localization-kit eval blind-score --dir evaluation --reports reports --out score.json
```

程序核验批次、映射和报告，统计双轮均完成的配对：候选获胜计 1、平局计 0.5、失败计 0，两轮取均值。单轮、未完成和拒评配对分别列出且不计分；两轮结论不一致也单独标记。缺批时输出阶段性统计，`complete` 表示全部批次均已提交，不表示质量达标；没有可评分配对时得分率为 `null`。保留比较报告、盲评目录和评审结果以便追溯；重新准备会生成新的随机批次。

## 测试集与对照

分别选取小说、字幕和游戏的代表性原文，记录来源、领域、条目、上下文、术语表及其版本。覆盖人名、主语省略、施受方向、控制码、拟声词、长句和断句等实际难点；保留测试集摘要和抽样方法。比较同一输入、可比的术语条件和质量规则，并记录模型 ID、revision、profile 和请求参数。

参考译文若来自某个候选模型，其字符相似度天然偏向该模型，只能用于发现偏离，不能独立证明质量。模型无法识别或验证当前权重版本时，应在报告中注明。

## 自动检查

以下是评测时应记录的指标；当前 `eval compare` 只汇总作业中已有的状态、警告和违规，不会自动生成全部指标。

统计成功、失败、行数及占位符错误、未翻译、拒答和警告，并记录术语满足率与耗时。`hard` 术语满足率、繁简和字符相似度可作为排查信号，不能代替人工对原文核查；相关错误可能集中在少量词条，平均分会掩盖严重漏译。

## 盲评和人工抽查

每次将同一原文的两个匿名译文交给评审，交换位置再评一次；评审先列出误译、漏译、增译、人称或方向等证据，再判断忠实度和表达。对位置交换后结论不一致的条目、关键术语及明显质量差异做人工抽查。需要试听的字幕应能定位原始音轨及时间。

模型评审可能存在位置、自我偏好、长度偏好和评价标准同源等偏差；可用独立评审标准、位置平衡和人工锚点缓解。按作品或音轨分组报告，不能把同一作品的每行都假设为相互独立。

## 验收记录

保存测试集与配置、候选结果、失败与警告、匿名映射、评审标准、逐项结论和人工抽查记录；说明遗漏、样本数量、时间与结论适用范围。完成格式和接口验收后，仍须单独判断翻译质量是否满足具体作品的交付要求。
