# ADR-0003: 游戏文本与通用 JSONL 交接边界

日期：2026-11-17 | 状态：accepted

## Context

游戏引擎文本通常包含引擎专属控制码（颜色、变量占位符、停顿标记、选择支结构等），直接把这些引擎格式接入本地化核心会引入大量耦合逻辑。

## Decision

游戏侧与 `localization-kit` 通过 **稳定条目 ID 的通用 JSONL** 交接：

1. **前置准备（游戏侧）**：负责条目筛选、按事件分组、保护控制码为安全占位符，并生成输入 JSONL 与本地还原映射文件。
2. **核心处理（localization-kit）**：读取输入 JSONL 完成初翻、润色与校对，通过 `export` 交付译文 JSONL，并通过 `results` 提供失败/待复核条目明细。
3. **写回还原（游戏侧）**：**映射文件由调用方自行保管**；恢复阶段核对 ID、原文、事件分组与占位符数量，还原控制码后执行游戏内校验。

## Alternatives Considered

- **在 `localization-kit` 内置各游戏引擎适配器**：需要维护多种引擎的二进制/脚本解包格式，且难以覆盖具体游戏的定制控制码。
- **导出时透传全部私有元数据**：会模糊文本阶段输出契约，并增加状态存储体积。

## Consequences

1. 游戏工具可自由选择完整相同事件去重（`deduplicate-events`）等游戏专属优化，而不影响核心按输入与上下文签名复用的机制。
2. 代表事件出现失败或人工修订时，游戏侧需显式处理展开保护，避免误覆盖独立修改。
