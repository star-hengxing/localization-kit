# ADR-0004: 追加式作业状态与崩溃恢复

日期：2026-11-17 | 状态：accepted

## Context

长文本或整本作品翻译通常包含数千条记录、多轮人工/Agent 修订以及长时间的模型请求。翻译过程中可能发生进程中断、网络超时或并发访问（如后台初翻期间查询状态）。

## Decision

采用 **作品文件锁 + 追加式持久历史 `results.jsonl` + 可重建阶段视图** 设计：

1. **单一真相源**：`results.jsonl` 按条目追加机器翻译结果、人工修订、阶段完成标记与上下文签名。各阶段的 `translation.json` 视图由持久历史重放重建。
2. **批次原子性**：每批结果校验通过后先写入恢复记录再提交；若批次任一条目校验失败，整批保持未提交。中断遗留的完整恢复记录在下次可写打开时自动前滚补齐；只读打开时报告待恢复状态。
3. **细粒度加锁**：作品锁仅在领取与提交期间持有；初翻持锁运行期间，状态查询通过读取定期刷新的只读进度快照实现无锁查看。

## Alternatives Considered

- **直接原地覆写单一状态 JSON**：进程中途崩溃容易写坏整个状态文件，且无法追溯历史版本或保护人工修订免受覆盖。
- **全程独占读锁**：导致长任务运行期间用户无法执行 `status` 查看进度。

## Consequences

1. 任何阶段的视图损坏或缺失均可从 `results.jsonl` 完整重建。
2. 人工修订绑定底稿版本与上下文签名，跨版本重跑或并发提交时可精确检出冲突并保护人工成果。
3. 已有作品的历史记录哈希链约束必须保持向后兼容。
