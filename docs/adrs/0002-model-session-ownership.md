# ADR-0002: 模型服务直连与会话所有权边界

日期：2026-11-18 | 状态：accepted

## Context

本地或远程部署大语言模型时，常涉及显存准入、模型切换与服务生命周期管理。需要明确 `localization-kit` 客户端与外部调度器/部署方在模型会话上的职责划分。

## Decision

`localization-kit` **直连模型 API（OpenAI 兼容端点），不内置私有模型会话调度协议**：

1. 工具读取作品 `config.toml` 中的 `url`、`model` 与 `profile` 发送推理请求。
2. 外部调度方（如作业编排器或本地服务管理器）负责在启动 `localization-kit` 前完成模型拉起、会话申请与退出后的资源释放。
3. 当推理请求被外部中断或进程强杀时，客户端退出并不代表上游推理已终止，恢复前需由调用方确认上游服务状态。

## Alternatives Considered

- **客户端内置会话协议**：在 Go 客户端内维护服务申请、心跳续期与释放逻辑。这会把工具绑定到特定私有调度器，破坏独立运行时的通用性。
- **通用包装器完全接管**：由外部包装器拦截所有请求状态并代理转发。现阶段没有足够多异构使用方证明需要该层抽象。

## Consequences

1. 工具可无缝对接任意 OpenAI 兼容服务端（vLLM、llama.cpp、商业 API 或本地网关）。
2. 故障恢复由作业级 `results.jsonl` 负责；在外部取消或超时后续跑前，调用方应先确认服务端并发队列已空闲。
