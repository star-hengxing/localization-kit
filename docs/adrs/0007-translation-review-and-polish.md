# ADR-0007: 三阶段翻译流程与审校分离

日期：2026-11-17 | 状态：accepted

## Context

大语言模型的初翻虽然往往通顺，但仍可能隐藏漏译、人称漂移或施受方向反转。如果直接用无依据的重写式润色覆盖初翻，不仅难以发现已有错译，还可能在游戏/剧情文本中引入忠实度退化。

## Decision

将文本本地化拆分为 **初翻（`translate`）→ 润色（`polish`）→ 校对（`proofread`）** 三个独立阶段，并引入显式审查步骤：

1. **初翻与基础检查**：模型按原文、术语和 `profile` 生成初翻并执行基础规则检查；阻断项触发重试或标为失败，警告随条目保存。
2. **先审查后润色/应用**：通过 `review prepare|run|validate` 生成忠实度与问题报告；`polish apply` 仅在目标全部通过忠实度审查时才应用候选改动并追加修订记录。
3. **双轨执行与统一契约**：润色和校对既支持通过模型 API 批量执行（`run --stage`），也支持人工或 Agent 按批领取、提交和释放（`next` / `submit` / `release`）。两者共用同一套底稿校验、上下文签名核对和 `StageCompletion` 记录。

## Alternatives Considered

- **单阶段直出 + 自动分数筛选**：仅靠自动流畅度或翻译腔阈值决定是否重写。实验表明单一自动指标无法发现语义错译，且全量重写风险不可控。

## Consequences

1. 任何阶段的人工编辑（`edit`）都会绑定当前底稿哈希与上下文，防止后续重跑静默覆盖人工修改。
2. 审查报告与润色候选绑定生成时的底稿版本；底稿变更后，旧意见不可直接应用，需重新生成或复核。
3. 阶段划分带来额外的状态与确认步骤，团队可根据作品交付要求按需选择导出阶段（`--stage translate|polish|proofread`）。
